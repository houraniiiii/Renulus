## Work sequence

1. **Product map.** Use the confirmed brief to describe a quick question, a
   focused study session, a daily-practice discussion, a scored test and an
   update that changes a saved learning point. Map their transitions before
   drawing a large collection of screens.
2. **One visual system.** Retain the selected Renal flow logo and calm medical
   character. Establish typography, spacing, colour roles, focus treatment and
   reusable states. Impeccable guides task clarity and craft; Interface Design
   guides hierarchy, density and consistent components. They inform one system.
3. **Figma library and complete journeys.** Build reusable navigation, mode
   indicators, answer entry, feedback, source references, saved learning and
   connection controls. Compose complete Windows flows using these components.
   Keep scored Test visually and behaviourally distinct from Explain.
4. **Prototype interruptions as well as success.** Include a missing model
   connection, cancellation, timeout, unavailable source, unsaved case, resumed
   test, withdrawn question and corrected learning note. Design window resizing,
   text scaling, keyboard order and focus. Windows-only does not mean a fixed
   screenshot size.
5. **Implementation handoff.** Reuse Hermes's Electron/React desktop foundation.
   Exercise typography, streaming, equations, tables and accessibility in the
   actual renderer. Implement production components and compare them with Figma.
   Capture component names, states and tokens in the repository. Use Code Connect
   where supported by the connected account/tooling; otherwise retain explicit
   Figma-node/component references.

Code Connect supplies implementation references alongside design components.
It supports the design-to-code mapping; working behaviour and component tests
remain implementation responsibilities.
([Official integration documentation](https://developers.figma.com/docs/figma-mcp-server/code-connect-integration/))

## Before implementation

Rounds 1–3 settle subscriptions, broad nephrology plus ESENeph, personal Windows
computers, broad inputs and the main interaction choices. Design and validate
journeys across nephrology; do not centre the product on one demonstration
subject. The [stage plan](../../planning/IMPLEMENTATION_PLAN.md) requires real
connected flows: a Figma prototype alone is never implementation completion.

The existing project brief is the product context. Do not label Renulus as a
web/mobile product merely to satisfy a tool template. Record Windows-specific
context explicitly when creating later design files. Detailed styling is still
open; the selected logo does not by itself determine every interface colour.
