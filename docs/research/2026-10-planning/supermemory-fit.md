# Supermemory fit for Renulus

Access date for every external source: **2026-10-04**. Public documentation, licences, release metadata and source were read; no candidate software was installed or executed and no inference API was called. Capabilities below are documented or code-observed, not tested. The latest user instruction confirms the Hermes fork and all seven round-3 recommendations. The generation allowlist remains GPT 6.1 Sol, GPT 6 Astra, GPT 6 Luna, MiMo V2.6 Pro and DeepSeek V4.1 Flash.

**Recommendation: not selected for the core under the confirmed constraints.** Supermemory offers substantial reusable functionality and an existing Hermes integration. However, its documented generative/extraction routes do not establish compatibility with the selected subscriptions, and its separate engine has unresolved redistribution terms. Hosted use adds a separate service/account and economics. Keep it optional until those gaps are resolved; embedding/OCR dependencies warrant their own evaluation. Proceed with Hermes reuse and the maintained local components below; no major user decision is needed now.

**Exact upstream and licence boundary.** These are research pins, not installed dependencies:

- [supermemoryai/supermemory](https://github.com/supermemoryai/supermemory/tree/7cc19fa34683a4fe74166ee5d794d271a21b5a92), commit `7cc19fa34683a4fe74166ee5d794d271a21b5a92`: the opened [LICENSE](https://github.com/supermemoryai/supermemory/blob/7cc19fa34683a4fe74166ee5d794d271a21b5a92/LICENSE) is MIT.
- [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent/tree/af90026aa09949579bd423d24def3d38f743cde0), commit `af90026aa09949579bd423d24def3d38f743cde0`: the opened [LICENSE](https://github.com/NousResearch/hermes-agent/blob/af90026aa09949579bd423d24def3d38f743cde0/LICENSE) is MIT. This verifies the intended Hermes upstream.
- Its [catalogue entry](https://github.com/NousResearch/hermes-agent/blob/af90026aa09949579bd423d24def3d38f743cde0/plugin-catalog/supermemory.yaml) pins Supermemory’s maintained community plugin, [supermemoryai/hermes-supermemory](https://github.com/supermemoryai/hermes-supermemory/tree/91405dd00fdf2a0b3515b25c25557598f6793299), version 1.0.1, commit `91405dd00fdf2a0b3515b25c25557598f6793299`; its opened [LICENSE](https://github.com/supermemoryai/hermes-supermemory/blob/91405dd00fdf2a0b3515b25c25557598f6793299/LICENSE) is also MIT.

The public Supermemory tree contains UI, MCP, integration wrappers and supporting libraries; its [web client](https://github.com/supermemoryai/supermemory/blob/7cc19fa34683a4fe74166ee5d794d271a21b5a92/packages/lib/api.ts) calls a configurable backend, defaulting to the hosted API. An SDK or UI checkout does not supply the full engine. [Self-hosting documentation](https://supermemory.ai/docs/self-hosting/overview) explicitly identifies the server as a binary from a separate non-public codebase. [Release 0.0.7](https://github.com/supermemoryai/supermemory/releases/tag/server-v0.0.7) describes a 10,000-document “lite” licence limit. The [0.0.8 tag’s LICENSE](https://github.com/supermemoryai/supermemory/blob/server-v0.0.8/LICENSE) also says MIT for the public source; it does not establish the separate binary’s redistribution rights. Full server terms were not located.

**Windows and dependencies.** The [0.0.8 release manifest](https://github.com/supermemoryai/supermemory/releases/download/server-v0.0.8/manifest.json) includes `windows-x64`, and its [asset listing](https://api.github.com/repos/supermemoryai/supermemory/releases/tags/server-v0.0.8) includes a native executable. This contradicts the [quickstart’s](https://supermemory.ai/docs/self-hosting/quickstart) macOS/Linux-only platform list. Native Windows distribution exists; successful installation, operation and ARM64 support are unverified. Do not claim WSL or remote hosting is compulsory. The [configuration docs](https://supermemory.ai/docs/self-hosting/configuration) also disclose unsafe network exposure in published 0.0.8; the promised loopback/authentication fix belongs to a later release.

Local storage and graph processing are embedded, without a separately provisioned database. Nevertheless, summaries, contextual chunking and fact extraction require an LLM endpoint/key; the documented OpenAI-compatible default is `gpt-5.1`, outside Renulus’s allowlist. High-fidelity PDF/image understanding requires Gemini or Vertex credentials. [Configuration evidence](https://supermemory.ai/docs/self-hosting/configuration).

Embeddings separately default to local `Xenova/bge-base-en-v1.5`; remote alternatives require embedding endpoints/credentials. The five-model selection governs generation, not a categorical ban on embedding/OCR components. Evaluate those separately for licence, Windows packaging, resources, data egress and costs; no new paid provider or user-managed inference requirement is implicit. An OpenAI-compatible endpoint might accommodate an allowed Go model, but subscription authentication, routing and extraction remain unverified. [Embedding documentation](https://supermemory.ai/docs/self-hosting/embeddings).

The hosted service avoids owner-operated infrastructure, but needs a Supermemory account/key and uses proprietary extraction models. [Billing](https://supermemory.ai/docs/overview/billing) offers a free allowance, then separate metered plans/credits; it is not included in the selected subscriptions. Standard PDF/OCR extraction is documented across tiers, while advanced figure descriptions require Scale/Enterprise. The local engine omits managed connectors/MCP, collects disableable telemetry, and uses a hosted reader for URLs. [Deployment comparison](https://supermemory.ai/docs/self-hosting/overview).

**Actual Hermes integration.** The pinned [plugin README](https://github.com/supermemoryai/hermes-supermemory/blob/91405dd00fdf2a0b3515b25c25557598f6793299/README.md) specifies plugin installation/enabling, the Python Supermemory SDK, `memory.provider=supermemory`, `SUPERMEMORY_API_KEY`, and optional `base_url`. It supplies `supermemory-save`, `supermemory-search`, `supermemory-forget` and `supermemory-profile`, with snake-case aliases. This is genuine upstream reuse, although [Supermemory’s integration page](https://supermemory.ai/docs/integrations/hermes) still describes an in-tree provider.

[Source inspection](https://github.com/supermemoryai/hermes-supermemory/blob/91405dd00fdf2a0b3515b25c25557598f6793299/__init__.py) shows automatic recall/capture enabled by default, conversation documents grouped into four-hour session windows, retrying writes, and mirroring memory additions. Session end flushes pending turns, rather than independently ingesting the whole transcript. It exposes no PDF-import/library workflow. Its search-tool response includes IDs, content and similarity, requiring adaptation for full provenance.

**Raw cases, deletion and portability.** Turning off `auto_capture` alone does not disable explicit saves or mirrored memory additions. Capture cleaning removes injected context and inline image data, not patient identifiers. Learning takeaways, library material and explicitly saved cases therefore need separate application-enforced retention and retrieval boundaries. Case text must also stay out of automatic recall queries. Container tags organise data; they cannot substitute for deciding what may be transmitted or retained. These are consequences of the inspected plugin behaviour, not evidence of safe default separation.

The plugin’s forget action calls memory forgetting: [the API documents soft deletion](https://supermemory.ai/docs/recall/memory-operations), preserving the record. [Document deletion](https://supermemory.ai/docs/ingestion/document-operations) is described as permanent; [container deletion](https://supermemory.ai/docs/api-reference/container-tags/delete-container-tag) covers documents and memories. These sources do not establish complete propagation through derived profiles, shared memories, uploaded files, backups or Hermes-local copies. The plugin mirrors additions, not edits/deletes. Renulus would need explicit cascading deletion and checks preventing retry or connector re-ingestion.

Document/chunk/history APIs make application-level export plausible; they do not demonstrate a lossless graph/vector export or portable restore. Local directory backup and changing `baseURL` are [documented](https://supermemory.ai/docs/self-hosting/quickstart), but endpoint compatibility is not data migration. Keep canonical originals, source locators, revisions and learning records independent of any optional memory index.

**Two maintained local reuse candidates.**

1. **pypdf for PDF text extraction.** [Version 6.19.0, released 2026-09-16](https://pypdf.readthedocs.io/en/stable/meta/CHANGELOG.html), provides pure-Python page-based extraction without a model/key/service. Opened [licence at research commit fa9d5cb](https://github.com/py-pdf/pypdf/blob/fa9d5cbafbb4c8f6bc75b5feca8826d5ffbc3137/LICENSE): BSD-3-Clause. [Extraction documentation](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) supports layout extraction but warns about difficult coordinates and scanned pages. It supplies neither OCR nor reliable table/figure interpretation. Windows packaging and limits need validation.
2. **SQLite FTS5 for local retrieval.** [SQLite 3.53.4](https://www.sqlite.org/changes.html), released 2026-07-24, has [Windows distributions](https://www.sqlite.org/download.html); the opened [copyright declaration](https://www.sqlite.org/copyright.html) dedicates deliverable code to the public domain. [FTS5](https://www.sqlite.org/fts5.html) supplies lexical ranking, BM25 and snippets without embeddings, keys or a server. It is not semantic vector search. Chunk boundaries, terminology expansion, source links and index deletion remain application work.

**Proposed working-product stages, for later implementation authorisation.**

1. Reuse Hermes’s memory lifecycle and persistent records to deliver inspect/edit/delete/export and restart/resume, with automatic learning takeaways and explicit case Save.
2. Add pypdf extraction and FTS5 to deliver an importable personal library, cited passage retrieval and deletion. Verify CKD, glomerular disease, dialysis and transplantation material; no single-topic restriction.
3. Complete scanned-PDF/image handling through verified capabilities of the selected subscriptions, plus current-source lookup and interruption recovery. Evaluate retrieval misses and citation fidelity across domains. Do not call broad input support complete while extraction gaps remain, or introduce another model silently.
