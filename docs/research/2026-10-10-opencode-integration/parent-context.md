## OpenCode context seam

At source `4b6fea2875e4f2e3e8a8fee181803e54f7056845`, the session compaction hook can supply a result and skip the ordinary model request. Context, compaction, title and generation are distinct hooks/request kinds. The implementation retains recent conversation beside a supplied summary; the stock summarizer appends its coding-oriented template after hooks. Therefore replacing only the main agent prompt is insufficient. [Hook contract](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/plugin/src/promise/session.ts), [compaction implementation](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/compaction.ts)

A supplied result is useful as a configurable adaptation seam, but a hook exception alone is not an established fail-closed control. The selected host must prevent stock compaction dispatch when required educational context preparation is absent or fails. Native provider checkpoints are route-specific; changing provider/model/endpoint requires compatible history reconstruction rather than replaying opaque state elsewhere. [Model-request assembly](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/model-request.ts), [checkpoint provenance](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/provider-context.ts)

## Proposed Renulus adaptation to challenge in later waves

1. OpenCode owns live conversation lifecycle and compaction scheduling. Its authoritative transcript is the source for a **derived** summary tree and persisted view. Do not create another writable chat log or a second agent scheduler. Keep canonical learner memory and Library evidence separate from this conversation-navigation index.
2. A context manifest records the exact policy/instruction versions, learner-memory revisions, source/passages and revisions, transcript range, route/capability evidence, recent verbatim exchanges and selected history nodes. Enforce the current retention/suppression epoch at final dispatch and at every zoom/read operation.
3. Pin current user task, active constraints, corrections, exact unresolved values/units and pending tool results. Use summaries only to navigate retained history. For facts used in an answer or publication, recover exact evidence; an old assistant answer never becomes a verified clinical source. Permit lexical/reference search as well as zoom so an omitted clue does not make originals undiscoverable.
4. Keep one instruction authority. Stable policy and tool schemas may form a cacheable prefix, while time, source currentness and mutable learner evidence remain explicit versioned data. Correctness and revocation override cache reuse. User text or retrieved material cannot install plugins or escalate permissions.
5. Configure 128K and 256K **requested token ceilings**, but calculate admitted input from the minimum of requested ceiling, model limit, endpoint/account proven limit, minus output/tool-result/safety reserves. Missing evidence is unknown, not an inferred 200K window. A lower limit produces a visible profile status; no silent claim that 256K is active.
6. Use token accounting appropriate to the exact route with calibrated estimation when exact counts are unavailable. Bound images/tool schemas as well as text. Byte size controls stored views; it does not replace token budgeting. Do not discard images without an explicit unavailable-content marker and reacquisition path.
7. Start with evidence-aware educational compaction and exact history retrieval. Add the hierarchical view behind configuration after recall, correction and deletion tests pass. Summary generation is metered work under its own role; it uses the same dispatch control, bounded budget and recovery rules as other generation. A failed/lagging summary preserves original history and reports context readiness rather than silently omitting messages.
8. Nodes reference immutable source ranges plus revision and retention epochs. A correction or deletion invalidates affected ancestors and persisted views immediately; rebuild is derived work. Keep deletion tombstones across backup restore. Temporary conversations get volatile context/tree state and no learner-memory capture unless the user explicitly promotes eligible material.

## Acceptance that remains implementation work

Compare recent-only, educational compaction and tree-assisted history against exact provenance targets, including adversarial instructions inside quoted text. A scripted model proves plumbing; real model quality and actual subscription limits require separately recorded acceptance.
