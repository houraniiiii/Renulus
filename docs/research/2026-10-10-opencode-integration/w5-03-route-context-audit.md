1. **H08 needs one instruction-version rule.** Its “required current instructions” and changed-guidance invalidation wording can contradict S1/S2's pinned-run rule. Specify: immutable run guidance plus current mandatory revocations; ordinary edits affect new runs, and explicit migration changes existing bindings. Also order user requests versus optional skill guidance explicitly; neither changes executable authority. The upstream [instruction loader](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/instructions.ts#L35-L78) deduplicates paths and rereads file contents after those paths leave visible history; this is not content-version pinning. **F0/M1, H08:** resolve content hashes from the existing configuration authority and test edit→compact→reopen with/without migration, plus revocation and contradictory quoted instructions. No second instruction engine is needed. [H08](../../planning/opencode-v2/tickets/08-apply-versioned-instructions-and-skills-to-a-learning-task.md).

2. **The final budget requirement must cover auxiliary output as well as main input.** H10 correctly counts the assembled request after hooks, schemas, media and history expansion. However, upstream [request preparation](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/model-request.ts#L251-L302) supplies default output limits only for primary/compaction; title/generate retain provider defaults, and hooks may remove limits. **F0, H03/H04; H10 supplies accounting:** explicitly require bounded effective output and input/context checks for every admitted request kind. Check input and output caps separately as well as their combined window; block unknown enlarged profiles. These are integration requirements, not an implemented guard. [H03](../../planning/opencode-v2/tickets/03-use-the-selected-subscription-for-tools-and-images.md), [H10](../../planning/opencode-v2/tickets/10-continue-an-evidence-aware-128k-or-256k-conversation.md).

3. **Define the unit of an attempt before enabling the loop.** “One attempt per stage” is ambiguous for a tool round trip requiring an initial call and a continuation. Separate loop steps from retries, with all outbound calls debiting a bounded parent-operation allowance. Upstream [title selection](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/context.ts#L95-L118) can choose a small model; [title generation](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/title.ts#L127-L133) can retry on primary. [Compaction](https://github.com/anomalyco/opencode/blob/4b6fea2875e4f2e3e8a8fee181803e54f7056845/packages/core/src/session/compaction.ts#L287-L309) has a template nudge and separate overflow handling. **F0, H04:** freeze numeric proposed allowances and test title-disabled zero calls, tool continuation, summary/repair, child, transport fallback and restart against one durable accounting contract. Preserve the current generation counter's meaning: `runtime/renulus/assessment/generation_service.py@76cfdff` counts 12 batch calls, not every auxiliary inference request. [H04](../../planning/opencode-v2/tickets/04-adjust-roles-and-configuration-with-visible-activation.md).

4. **Make role defaults and promotion ownership executable requirements.** Inheritance is a sensible initial recommendation, not evidence that one selected model is best for every task. The concrete Automatic ordering, disabled-role precedence and evaluation proposal currently reside primarily in [W3-02](w3-02-capabilities-evaluation.md). H04 should adopt or explicitly revise them, assign F0 plus each consuming domain owner, and require recorded evaluation before specialized defaults. Keep any proposed 22/24 threshold labelled provisional. At `runtime/renulus/runtime/manager.py@76cfdff`, Automatic chooses the first allowlisted catalogue match, then the first allowed ID; explicit/saved choices persist. Preserve that behavior without inventing quality rankings. H03's 401 defect remains reproduced below; retain its repair acceptance.

5. **Resolve whether the optional tree blocks cutover.** H11 calls the tree optional, yet [H18](../../planning/opencode-v2/tickets/18-delete-and-restore-a-consistent-migrated-learning-profile.md) and [H20](../../planning/opencode-v2/tickets/20-cut-over-the-windows-client-with-a-recoverable-release.md) require H11. If tree implementation is required before release regardless of activation, label that decision explicitly. **Minimal proposal, integration/M1/M5:** make exact-history retrieval an explicit H10 acceptance item; gate baseline restore/cutover on that contract. Gate tree-specific invalidation/evaluation on enabling the tree. This preserves compaction-first delivery without weakening deletion. The [immutable article](https://gist.githubusercontent.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/raw/4c09901baa3685852bf252cdb70ace81d01d6be5/optchat.md) actually specifies UTF-8 bytes, 512-byte nodes and 128,000→64,000-byte view reduction. Its up-to-five shortening attempts are not a selected Renulus retry policy. Neither its sizes nor cache simulations establish token capacity or recall. [H11](../../planning/opencode-v2/tickets/11-recover-older-detail-through-a-derived-history-view.md).

6. **H19's scope is correct.** Future opt-in providers supersede the historical exclusion without changing initial defaults. Preserve deployment/template/protocol-specific qualification and disabled native checkpoints. Completing the context-accounting contract must not require an optional endpoint to support 128K/256K; lower verified windows remain legitimate. Account access, protocol success and task quality require separate evidence. No extra routing authority is warranted. [H19](../../planning/opencode-v2/tickets/19-validate-an-optional-additional-or-local-provider.md).

**Next-wave closure, proposed.** F0 should own a single request-admission fixture reused by H03/H04/H10, asserting the emitted route, final prompt size, enforced output cap and consumed permits together.
