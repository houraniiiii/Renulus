**Review 16 — Native Windows packaging and headless operation**

2026-10-10; public source and repository implementation reads only. Pins: Renulus `528025ff0b22477c12ee1512e0e7d15297a6e888`; bundled Hermes `af90026aa09949579bd423d24def3d38f743cde0`; inspected Hermes `dce1e9b37581dd62e480a9064dc04a709c2940d3`; Pi v1.1.0 `abe508e1b89912adde45528136c3221eb69acdd7`; OpenCode v2branch `55dde8810d8a859c0a21e42491ae7d5801fb49ef` (source version 2.0.26). Linked ranges use raw-file line numbers.

**Conclusion (judgment):** Windows/headless requirements do not eliminate any foundation. On this deployment axis, prefer Pi's explicitly configurable library host with Renulus's managed Python domain worker. Hermes can consolidate execution and domain helpers in Python; OpenCode v2 offers a real embedded Node route and compiled Windows CLI, but adds native dependency and artifact-identity checks. This is a scoped preference, not a replacement decision or implementation authorisation. Application clients can be optional in all three.

Five verified findings support that conclusion:

1. **Hermes is not inherently a desktop application or Linux service.** Its [programmatic transports](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/website/docs/developer-guide/programmatic-integration.md#L9-L39) include stdio ACP/JSON-RPC and HTTP; [AIAgent's conversation method](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/agent/turn_facade.py#L19-L46) is a Python call. Upstream's [manifest](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/pyproject.toml#L10-L15) allows older Python for updating, while [PM actually requires 3.14](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/pm/pyproject.toml#L1-L11). Its stock local terminal [requires Bash](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/tools/environments/local.py#L514-L527). Both [bundled](https://github.com/NousResearch/hermes-agent/blob/af90026aa09949579bd423d24def3d38f743cde0/pm/shell.py#L1-L21) and [inspected](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/pm/shell.py#L1-L21) shell resolution support staged Git-for-Windows Bash; this need not mean doctor-installed Git. [Local is the default terminal backend](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/tools/terminal_tool.py#L1-L7); Docker and remote backends are alternatives, not necessary domain infrastructure.

2. **Pi's SDK can omit shell tools.** The [package requires Node >=22.19.0](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/package.json#L105-L107); its [SDK embeds in Node or Bun](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/sdk.md#L1-L5) and exposes [tools/noTools/customTools](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/sdk.md#L96-L116). A [JSONL child-process mode](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/rpc.md#L1-L18) provides another headless boundary. [Native Windows documentation](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/windows.md#L3-L47) distinguishes Git Bash for stock Bash/`!` commands, optional PowerShell for model tools, and optional WSL. Thus Bash is conditional on the selected execution surface. [Bun compilation is a separate binary build](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/package.json#L39-L45), not a Node SDK runtime requirement; an npm install is not a sealed Windows application bundle.

3. **Pi durable is a real, separately packaged adoption unit.** Its [Node SQLite adapter](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/storage/sqlite/node.ts#L1-L14) uses `node:sqlite`; [storage documentation](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L536-L545) permits local SQLite/JSONL but requires one process owner. Cloudflare is another backend, not mandatory hosting. Its Node environment [runs argv directly](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/env/node.ts#L663-L680); string commands instead use its [Bash resolver](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/env/node.ts#L217-L258). This supports direct Python-worker invocation without shell parsing. The library is [explicitly experimental](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L1-L7), and is absent from [coding-agent dependencies](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/package.json#L49-L73): stock AgentSession integration must not be assumed.

4. **OpenCode v2 does not require a separately listening server or Bun runtime for every host.** Its [embedded host](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/sdk/src/internal/host.ts#L30-L70) returns an in-process Fetch handler, with an in-memory database default. The [Bun SDK build targets Node](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/sdk/script/build.ts#L11-L22), leaving dependencies external. [Runtime conditions](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/package.json#L32-L68) select Node/Bun implementations; [Node PTY loads a native package](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/pty/pty.node.ts#L1-L13). Headless does not erase that dependency closure. [Windows shell selection](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/shell/select.ts#L95-L108) supports PowerShell, Git Bash and cmd; [CLI build targets](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/cli/script/build.ts#L49-L51) include Windows x64/ARM64. The [published SDK 2.0.26 metadata](https://registry.npmjs.org/@opencode/sdk/2.0.26), read October 10, declares Effect rc.112 and lacks gitHead; the [branch declares rc.118](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/package.json#L83). The [public/default CLI 1.18.35](https://registry.npmjs.org/opencode-ai/latest), observed October 10, does not negate SDK publication or establish source/artifact equivalence.

5. **The existing Python helpers are reusable packaging assets under every foundation.** Renulus [pins embedded CPython 3.14.4](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/apps/desktop/scripts/stage-backend.py#L18-L29), [copies dependencies and verified helpers](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/apps/desktop/scripts/stage-backend.py#L205-L237), and [spawns python.exe directly with windowsHide](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/apps/desktop/electron/backend.ts#L30-L49). Source configures [FastEmbed CPU/local files](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/knowledge/engines.py#L105-L112), [Docling CPU OCR without remote services](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/knowledge/engines.py#L345-L375), [local LanceDB](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/knowledge/engines.py#L403-L415), and [Mem0/local Qdrant](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/memory/engine.py#L113-L140). No Bash, WSL, Docker or generative server is inherent to these domain calls. [ANTLR's sdist needs developer-side wheel preparation](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/packaging/runtime/requirements-helpers.txt#L10-L15), illustrating why doctor-side pip/setup is inappropriate.

**Tradeoff/proposal:** Pi adds a managed JS runtime beside Python, but offers explicit tool/environment seams. Borrow Renulus's embedded-Python delivery, manifest validation and owned-child lifecycle regardless of foundation; borrow OpenCode's optional embedded transport pattern. Keep processes local and Renulus-managed; no owner-hosted service or inference is proposed. Keep canonical source/learner/assessment SQLite authority in domain services, distinct from harness transcripts and derived indexes. Closing the application currently stops its [owned backend](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/apps/desktop/electron/main.ts#L151-L161); making harness lifetime independent is new integration work. Saved conversations require explicit lasting storage, including OpenCode's SDK.

**Uncertainty/change evidence:** No installation, application/service launch or native acceptance occurred. The preference could change if Pi's separate durable integration proves harder to package safely than OpenCode's complete native closure, or Hermes supplies an equally controlled headless host. Future authorised synthetic acceptance must cover developer-free PATH, absent Bash/WSL/Docker, Unicode/long paths, native DLL/WASM loading, SQLite ownership, worker death/cancellation and reopen with no client. The existing [Windows x64 wheel register](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/packaging/runtime/windows-cp314-wheels.json#L1-L6) does not establish ARM64 acceptance. Native feasibility also proves neither nephrology quality nor the five selected subscription/model routes.

Preserve the [dated rejection rule](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/docs/DECISIONS.md#L142-L152) and [adapter max_retries=0](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/runtime/hermes.py#L104-L116) in adoption proofs. Authentication/quota/model/image failures stay visible without fallback; transient-network and restart-generation policies remain separate proposals. Gate automatic generation recovery in conservative proofs; process restart does not authorise another provider request. OpenCode's embedded host starts recovery, so changing process lifetime needs policy review.

Handoff: `docs/research/2026-10-10-harness-adoption/review-16-windows-packaging-headless.md`. Conclusion: prefer Pi's library boundary on this axis; retain managed Python assets. Strongest fact: Pi durable accepts direct argv execution, bypassing Bash for Python tools. Unresolved risk: untested Windows dependency closure and single-owner recovery across JS/Python processes.
