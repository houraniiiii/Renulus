**Review 10 — Execution durability, cancellation and duplicate effects**

2026-10-10. Source inspection only; no runtime, crash or provider tests. Ranges below are raw-file line numbers at immutable commits. Pins: Renulus `528025ff0b22477c12ee1512e0e7d15297a6e888`; bundled Hermes `af90026aa09949579bd423d24def3d38f743cde0`; inspected upstream Hermes `dce1e9b37581dd62e480a9064dc04a709c2940d3`; Pi v1.1.0 `abe508e1b89912adde45528136c3221eb69acdd7`; OpenCode v2 `55dde8810d8a859c0a21e42491ae7d5801fb49ef`, whose [manifest](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/package.json#L1-L4) declares 2.0.26. Public/default OpenCode 1.18.35 and historical Pi 0.73 are outside this review.

**Conclusion (judgment):** OpenCode v2 offers the strongest integrated execution-durability baseline of these stock harnesses. Its persisted admission and execution claims deserve adoption consideration independently of the prior Hermes choice. Borrow Pi's separate `pi-durable` replay classification and submission reconciliation. None removes Renulus's responsibility for canonical effect transactions. This scoped conclusion neither selects a replacement nor authorises implementation.

Five verified findings carry that judgment:

1. **Hermes has gateway recovery, beyond transcript saving.** Both pins persist an ownership token before publishing the active turn in memory; fresh crash-left markers become `resume_pending` ([bundled](https://github.com/NousResearch/hermes-agent/blob/af90026aa09949579bd423d24def3d38f743cde0/gateway/session_lifecycle.py#L123-L195); [upstream](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/gateway/session_lifecycle.py#L123-L195)). Upstream [startup](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/gateway/run_startup.py#L598-L649) synthesises a continuation turn; [reply recovery](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/gateway/run_startup.py#L751-L784) guards against regenerating a persisted final reply when its delivery ledger is enabled. Its overflow FIFO remains a [process-local list](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/gateway/session_state.py#L41-L50). These are gateway-specific mechanisms, not proof of durable admission for every AIAgent/SDK caller or a general domain-effect ledger.

2. **Pi coding-agent persistence and queues are different contracts.** [JSONL persistence](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/session-manager.ts#L1161-L1188) saves the first user prompt and subsequent entries. Agent steering/follow-up queues are [in-memory arrays](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/agent/src/agent.ts#L143-L174); transcript restoration does not make those pending admissions durable. [AgentSession.abort()](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/agent-session.ts#L2431-L2444) cancels retry, compaction, summary and agent work, then waits for idle. This is stock CLI/SDK behavior, distinct from Pi's durable library.

3. **Pi 1.1.0's separate durable library supplies materially stronger controls.** [Admission commits](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/submissions.ts#L53-L60) and [request-ID reconciliation](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/submissions.ts#L149-L175) retain queued submissions without creating another submission for a repeated conversation/request ID. [Tool intent](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/tool.ts#L85-L116) commits before execution, defaults replay to unsafe, and reruns interrupted tools only if recorded and current policies both say safe; otherwise it reports possible partial execution. [Reopen](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/scheduler.ts#L238-L269) returns running tasks to pending. [Conversation abort](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/scheduler.ts#L329-L351) durably withdraws queued inputs and marks owned tasks, excluding background boundaries unless explicitly requested. These are built-in library mechanisms; its subagent demonstrations remain examples.

4. **OpenCode v2 persists admitted work and execution ownership.** [Admission reconciliation](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/inbox.ts#L154-L201) and [SQLite inbox projection](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/inbox.ts#L277-L322) distinguish pending work from delivered messages. [Execution claims](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution.ts#L76-L145) commit with start events ([publication transaction](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/bus.ts#L317-L403)): deliberate stop releases the claim; shutdown preserves it. [Restart recovery](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution/restart.ts#L23-L61) explicitly allows at-least-once external effects and has durable resume accounting. The [embedded SDK](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/sdk/src/internal/host.ts#L30-L56) defaults to `:memory:` and starts recovery after plugin registration; an adopter must configure lasting storage and control that startup policy.

5. **Shell survival and cancellation are narrower than run durability.** Hermes [checkpoint recovery](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/tools/process_registry_checkpoint.py#L50-L110) reattaches surviving host PIDs as detached sessions with status/kill capability, without recovered output; it does not rerun commands. Pi's [shell executor](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/tools/bash.ts#L96-L163) spawns a process and attempts process-tree termination on abort. OpenCode's [Job registry](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/job.ts#L172-L175) is process-local despite durable notification markers; [restart](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution/restart.ts#L101-L135) reports formerly running shell jobs cancelled. Its [interrupt contract](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution.ts#L26-L40) acknowledges before cleanup settles. A cancellation receipt cannot undo a completed external effect or establish Windows child-process death.

Tradeoff (judgment): OpenCode integrates resumable sessions and [background-child recovery](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution/restart.ts#L138-L189), but its default recovery is too permissive for this adoption proof. Pi durable offers finer replay and cancellation controls through a separately assembled library. Hermes offers useful recovery within its gateway. None of these mechanisms establishes educational scoring correctness.

The [dated Renulus rule](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/docs/DECISIONS.md#L142-L152) specifically keeps authentication, quota, model and image rejection visible without automatic retries or fallback. The [adapter](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/runtime/hermes.py#L104-L116) sets `max_retries=0`. That rule does not independently settle every transient-network or restart policy. Preserve current conservative behavior in adoption proofs: interrupted/unknown generation waits for explicit user Retry, preserving the selected allowed subscription/model. Disabling transient retries alone is insufficient: Pi durable [request recovery](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/generation.ts#L184-L209) can resend a checkpointed request independently of its [error-retry policy](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/generation.ts#L477-L505); OpenCode's startup sweep is likewise separate.

**Proposed Renulus responsibilities:**

- Own durable admission IDs, payload digests, attempt IDs, parent/child ownership and cancellation states. Fence stale workers with an ownership generation; acknowledge admission after commit, and distinguish stop accepted from work settled. Saved transcripts remain context, not learner/assessment authority.
- Commit canonical mutations and outbox admissions together. Commit score plus submission state atomically, uniquely keyed by assessment attempt and pinned bank version. Give publication a stable source-revision/target operation key. Record deletion tombstones and revision fences before idempotent cleanup outbox work, preventing recovered workers from resurrecting deleted records.
- Keep local SQLite canonical; retain Docling/FastEmbed tooling and Mem0/LanceDB derived indexes. Reconcile ambiguous effect outcomes using receipts; replay only operations demonstrably safe or supported by receiver idempotency. External effects remain potentially at least once; exactly-once delivery is not claimed.

Unresolved: no Windows crash acceptance was run. Pi durable documents [single-process ownership and power-loss limits](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L536-L545); OpenCode recovery assumes the previous owner is dead. Evidence that would change the preference: a Pi durable integration proving explicit generation-recovery gating and canonical transaction integration, or failure to impose that gate on OpenCode. Future synthetic fault tests should cover crash after effect/before receipt, duplicate admission, cancellation during cleanup, child recovery, and deletion during indexing; verify one canonical score/publication and zero unapproved generation replays.

Handoff: `docs/research/2026-10-10-harness-adoption/review-10-execution-durability-cancellation.md`. Conclusion: prefer OpenCode v2's integrated durability pattern; borrow Pi durable's conservative tool replay. Strongest fact: OpenCode writes execution claims before running and explicitly admits repeated effects. Unresolved risk: restart recovery may repeat generation independently of disabled SDK retries.
