# Review 18 — maintenance, licensing and release adoption

2026-10-10. Research only; source and registry inspection, without installation or execution. Renulus baseline: `528025ff0b22477c12ee1512e0e7d15297a6e888`. Hermes imported pin: `af90026aa09949579bd423d24def3d38f743cde0`; inspected upstream: `dce1e9b37581dd62e480a9064dc04a709c2940d3`. Pi: v1.1.0, `abe508e1b89912adde45528136c3221eb69acdd7`. OpenCode: v2branch `55dde8810d8a859c0a21e42491ae7d5801fb49ef`, declaring 2.0.26. Links below identify those snapshots and raw file line ranges; registry observations are dated separately.

**Conclusion — maintenance axis only.** Prefer versioned library integration through Renulus-owned contracts; Pi agent-core/pi-ai are my strongest default candidate for that adoption model. Evaluate pi-durable separately behind a pinned compatibility boundary. Hermes remains a defensible source fork when its integrated capabilities justify downstream patches. OpenCode v2 is a credible optional SDK adapter, with source/artifact parity still requiring proof. This is an engineering judgment about adoption boundaries, not an overall foundation selection or implementation authorisation.

**Five verified facts govern that judgment.**

1. **Top-level licensing does not discriminate between the candidates.** Hermes, Pi and OpenCode each carry MIT licences, respectively crediting Nous Research, Mario Zechner and opencode. Retain the copyright and permission notices with copies/substantial portions; shipping their complete licence texts is the straightforward implementation. MIT does not itself require a downstream patch ledger. Dependency/native/helper terms remain independent: Apache-2.0 redistribution additionally requires its licence, notices on modified files, retained applicable source attribution and any supplied NOTICE attribution. Sources: [Hermes imported LICENSE L1–21](https://github.com/NousResearch/hermes-agent/blob/af90026aa09949579bd423d24def3d38f743cde0/LICENSE#L1-L21), [inspected Hermes LICENSE L1–21](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/LICENSE#L1-L21), [Pi LICENSE L1–21](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/LICENSE#L1-L21), [OpenCode LICENSE L1–21](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/LICENSE#L1-L21), [retained Apache text L91–123](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/apps/desktop/licenses/runtime-helpers/RapidOCR-Apache-2.0.txt#L91-L123).

2. **Hermes has concrete downstream provenance, but packaging is a separate contract.** Renulus records the acquired archive hash, upstream licence hash and R001–R003 original/patched hashes and rationales: [manifest L1–61](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/packaging/runtime/hermes-source.json#L1-L61). Preserve this pattern for every copied source unit. Inspected upstream sets Python 3.14, while its manifest permits older interpreters specifically for updater compatibility; it declares OpenAI 2.24.0 and maintains a lock workflow, but also contains a urllib3 range. Therefore its comments are not evidence that every dependency is exact-pinned or every allowed interpreter is supported. Sources: [.python-version L1](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/.python-version#L1), [pyproject L10–40](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/pyproject.toml#L10-L40), [range L94–98](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/pyproject.toml#L94-L98). Upstream rebasing must revalidate Renulus's bundled runtime and domain-engine compatibility.

3. **Pi exposes distinct package adoption units, not just a CLI fork.** Agent-core 1.1.0 exports a library, depends on pi-ai `^1.1.0`, and requires Node ≥22.19.0: [manifest L1–44](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/agent/package.json#L1-L44). Pi-ai separately declares provider dependencies including OpenAI 7.19.0: [L69–100](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/ai/package.json#L69-L100). External direct dependencies are exact-pinned; workspace dependencies remain ranged. The managed CLI installer uses an installation lock, whereas direct npm packages do not freeze transitives: [README L168–180](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/README.md#L168-L180). A Renulus library consumer therefore needs its own complete lock. SDK sessions also require explicit MCP/codemode extension assembly: [SDK L98–116](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/sdk.md#L98-L116). Package reuse reduces the chosen upstream surface; it does not supply Renulus orchestration automatically.

4. **Pi-durable is real, separately adoptable and explicitly experimental.** Its published [1.1.0 registry metadata](https://registry.npmjs.org/@earendil-works/pi-durable/1.1.0) identifies the package and integrity. The pinned [README L1–7](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L1-L7) warns that APIs change without notice. It documents restart/resume and request-ID reconciliation, not only transcripts: [L101–121](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L101-L121). It also exposes storage conformance tests: [L538–562](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L538-L562). None of this proves durable execution is wired into stock AgentSession, or establishes Renulus migration/purge semantics. Freeze its schema/API together and test recovery before adoption.

5. **OpenCode's source version and published SDK are different identities.** Source pins Bun 1.4.2 and Effect 4.0.0-rc.118: [root L5–8](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/package.json#L5-L8), [L81–85](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/package.json#L81-L85). The [published @opencode/sdk/2.0.26 metadata](https://registry.npmjs.org/@opencode/sdk/2.0.26), inspected October 10, instead has `dependencies.effect=4.0.0-rc.112`, exact companion packages and no `gitHead`; record `dist.integrity` independently. The [default CLI registry](https://registry.npmjs.org/opencode-ai/latest) returned 1.18.35; that does not negate the published v2 SDK. V2 deliberately changes plugin/server/client contracts: [migration L8–39](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/services/www/src/docs/content/migrate-v1.mdx#L8-L39). Neither a prerelease dependency nor a major-version migration proves general immaturity.

**Proposed adoption/update policy.** Retain Mem0 OSS, Docling/HybridChunker, FastEmbed, LanceDB and canonical SQLite through Renulus-owned services regardless of harness choice. Runtime documents/transcripts are operational records; separate-store commits need receipts/outbox reconciliation. Reuse source only with scoped licences and hashes; borrow design ideas without importing unused integrations. Optional adapters should not redefine canonical source, learner or assessment authority.

Pin source SHA, package integrity, complete dependency locks, interpreter/runtime artifacts, native Windows binaries, helper assets, schemas and notice inventory. Update through reviewed candidate releases: replay documented patches, inspect contract/schema diffs, then pass synthetic Windows conformance checks for streaming/tool results, cancellation/subagent settlement, crash recovery, export/restore/purge and cross-store reconciliation. For pi-durable, include its upstream storage suite.

Preserve exact selected subscription/model identities and visible authentication/quota/model/image failures. The current adapter explicitly sets [SDK retries to zero, L107–114](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/runtime/hermes.py#L107-L114); keep that conservative adoption-proof baseline. Transient-network retries and restart reconciliation require separately specified policies, not an inferred universal retry prohibition. No provider tests ran here.

Uncertainties that could change the conclusion: reproducible OpenCode SDK-to-source correspondence and equivalent Windows conformance could favour its packaged runtime; Pi public-contract churn or unworkable durable migrations/purge could favour Hermes's auditable fork. None of these checks establishes educational quality.

Handoff: `docs/research/2026-10-10-harness-adoption/review-18-maintenance-licensing-release.md`. Conclusion: Pi package integration preferred on maintenance grounds; pi-durable separately gated. Strongest fact: pi-durable explicitly permits unannounced API changes. Unresolved risk: persistence migrations/purge and source-to-package correspondence remain unverified.
