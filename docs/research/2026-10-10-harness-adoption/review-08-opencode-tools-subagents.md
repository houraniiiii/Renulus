# Review 08 — OpenCode v2 tools and subagents

**Synthesis clarification:** references below to disabling all automatic generative retries describe the conservative adoption-proof baseline. The October 6 confirmed rule specifically concerns actual authentication, quota, model and image rejection without automatic retry/fallback; transient-network and restart policies remain separate proposals. [Review09](review-09-route-control-authentication.md) resolves this scope. This distinction qualifies the earlier shorthand, rather than establishing a broader ban.

October 10, 2026. Renulus baseline: `528025ff0b22477c12ee1512e0e7d15297a6e888`; OpenCode v2 pin: `55dde8810d8a859c0a21e42491ae7d5801fb49ef`. Raw line numbers below were checked against this commit. Existing comparison and first-wave memos were leads. This is source inspection; no runtime, inference or Windows acceptance was performed.

**Conclusion — judgment:** OpenCode v2 is a credible candidate for Renulus's tools-and-subagents layer. A host can replace model-facing editing tools and teaching prompts, but the runtime retains project/directory identity. Borrow its typed registry, cancellation/progress contract and explicit child-job lifecycle. This review does not select a foundation or authorise migration.

1. **Domain tools fit the shipped registration API.** Tool editors add, update, remove and namespace tools. Definitions carry input/output schemas; results carry content/metadata, and Promise executors receive progress and an `AbortSignal`. A repeated effective name replaces the earlier entry. `codemode:false` exposes a direct tool; other tools enter Code Mode. A custom agent system prompt overrides the stock prompt. Editing capabilities are therefore replaceable, although session creation still resolves a project from `Location.directory`. 2. **Children have enforceable admission rules, with limited permission inheritance.** The built-in `subagent` starts fresh child sessions; foreground is the default, background returns immediately, and continuation accepts only a direct child of the calling session. Primary-only agents are rejected. An ancestor walk enforces `experimental.subagent_depth`, default **1**. Delegation asks permission against the selected agent ID. Model precedence is explicit override, agent model, then parent model; the “never override unless asked” wording is guidance, while availability is checked in code. Creation copies parent session permissions/metadata/location. Child execution merges the child agent's rules followed by those copied session rules; the last matching rule wins. This is not an intersection with the parent's agent policy. Permission updates target an individual session. [contract/model resolution, raw L29–101](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/tool/plugin/subagent.ts#L29-L101); [admission/model rules, raw L113–205](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/tool/plugin/subagent.ts#L113-L205); [inheritance, raw L285–288](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session.ts#L285-L288); [evaluation, raw L87–100 and L158–178](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/permission.ts#L87-L178); [updates, raw L82–87](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/session.ts#L82-L87).

3. **Concurrency and source authorisation are separate responsibilities.** The runner forks each local tool call, then awaits the fibers; the inspected dispatch loop has no concurrency cap. Code Mode also supports concurrent composition. Tool context identifies session, agent, message and call, with no corpus-source authority field; namespaces organise names rather than enforce source access. Registry denial filters tools, but execution does not automatically assert permissions on each argument: domain executors must validate source IDs and call the permission/domain service themselves. MCP's model-facing bridge gates a server/tool action using resource `*`, rather than document-level scope. [dispatch, raw L96–170](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/runner/step.ts#L96-L170); [Code Mode, raw L61–69](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/codemode/tool.ts#L61-L69); [context, raw L14–30](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/schema/src/tool.ts#L14-L30); [executor, raw L29–61](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/tool/runtime.ts#L29-L61); [MCP gate, raw L41–70](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/tool/mcp.ts#L41-L70).

4. **Closure has several distinct meanings.** Closing a registration's Scope removes its transforms. Background child jobs and completion observers explicitly outlive the launching plugin in a global Scope. Completion admits a synthetic parent message and normally wakes the parent; it returns final assistant text, not a typed domain finding. Foreground interruption explicitly interrupts/cancels the child. Session deletion interrupts execution, waits for idle, closes transport and recursively deletes descendants. That does not establish deletion of domain records, indexes or already performed side effects. Restart recovery is explicitly at least once. [registration disposal, raw L224–246](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/state.ts#L224-L246); [job ownership, raw L20–63](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/subagent-job.ts#L20-L63); [completion, raw L10–45](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/subagent-completion.ts#L10-L45); [wake, raw L275–317](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/session.ts#L275-L317); [foreground cancellation, raw L234–256](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/tool/plugin/subagent.ts#L234-L256); [deletion, raw L367–377](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session.ts#L367-L377); [restart qualification, raw L46–61](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/execution/restart.ts#L46-L61).

5. **Registered does not mean sandboxed.** The Promise SDK accepts plugin registrations; stock coding tools are themselves removable built-in plugins, except the guarded Console/provider and policy plugins. Configuration operations can remove exact IDs or wildcards and later re-enable them. Package loading checks managed integration policy, resolves/adds packages, imports them, and only afterwards validates the exported definition. Node imports use the main context; upstream expressly says policies do not sandbox plugin code. **Assessment:** ship reviewed, pinned extensions as trusted application code. MCP's remote invocation contract and Code Mode's confined model-side scripting are different trust boundaries; neither makes an arbitrary downloaded plugin safe. Arbitrary HTTP plugin import support was not established. [SDK registration, raw L57–65](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/sdk/src/promise.ts#L57-L65); [inventory/guards, raw L216–274](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/plugin/internal.ts#L216-L274); [operations, raw L27–56](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/plugin/supervisor.ts#L27-L56); [policy/import order, raw L44–60 and L98–134](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/plugin/module.ts#L44-L134); [Node import, raw L7–10](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/util/src/runtime/import.node.ts#L7-L10); [explicit sandbox limit, raw L213–216](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/services/www/src/docs/content/policies.mdx#L213-L216).

**Proposed Renulus boundary:** expose source retrieval, learner memory and assessment through domain services with corpus/source IDs, cancellation, bounded concurrency and idempotent writes. Reuse canonical local SQLite plus Mem0 OSS, Docling HybridChunker, FastEmbed and LanceDB as existing assets; transcripts and derived indexes remain separate from canonical authority. Exact subscription/model allowlists and the current prohibition on automatic generative retries require host enforcement, including child model selection and restart recovery. No policy change, mandatory paid generation API, hosted service or doctor-managed inference is proposed. These are adoption requirements, not implemented capabilities; retained choices are recorded in [DECISIONS](../../DECISIONS.md#confirmed-choices).

**Uncertainty and evidence that would change the judgment:** an authorised synthetic Windows SDK check must establish a domain-only catalogue/prompt, source-scope enforcement across children, defined child continuation/cancellation on parent Stop, deletion and plugin replacement, and controlled restart without forbidden generation. Failure to remove ambient editing assumptions or prevent unauthorised source access and repeated side effects would weaken candidacy. Successful checks would strengthen it. These contracts do not establish educational quality across nephrology.

Handoff: `docs/research/2026-10-10-harness-adoption/review-08-opencode-tools-subagents.md` — conditional candidate for extensible tools/subagents; strongest fact: the shipped registry can replace stock tools; unresolved risk: trusted plugins, copied permissions and at-least-once recovery need a verified Renulus policy boundary.
