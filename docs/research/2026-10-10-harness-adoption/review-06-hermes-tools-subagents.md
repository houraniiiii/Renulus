# Review 06 — Hermes model tools and domain subagents

**Synthesis clarification:** references below to disabling all automatic generative retries describe the conservative adoption-proof baseline. The October 6 confirmed rule specifically concerns actual authentication, quota, model and image rejection without automatic retry/fallback; transient-network and restart policies remain separate proposals. [Review09](review-09-route-control-authentication.md) resolves this scope. This distinction qualifies the earlier shorthand, rather than establishing a broader ban.

This reviews built-in Python registration/delegation source at both pins, without executing Hermes or calling providers. Links identify immutable files and raw line ranges; earlier memos were leads.

**Conclusion — engineering judgment:** Hermes is a credible substrate for nephrology evidence and learning workers if Renulus owns their tools, permissions, route policy and lifecycle. Reuse its dispatcher, fresh child conversations and progress/control machinery. The stock delegation defaults require adaptation before domain use. This scoped finding neither selects the overall foundation against Pi/OpenCode nor authorises implementation.

1. **Registration is an embedding seam, with host obligations.** Register a name, toolset, function schema and handler before constructing the agent. Handlers accept arguments plus compatible context kwargs and return a JSON string or supported multimodal envelope; synchronous/asynchronous handlers are supported. The agent loop checks its advertised tool names, but direct `registry.dispatch()` performs neither that check nor argument-schema validation/approval. Pre-tool-hook exceptions can proceed without blocking. Hosts must validate inputs and authorize resource operations inside handlers/canonical services. [B registration][b-register], [C dispatch][c-register], [agent catalogue][catalogue], [loop validation][validation], [hook failure][hooks].

2. **Task context is fresh; provider policy is inherited or configured.** Each child is a new `AIAgent`, receives its own goal/context, skips normal memory loading, copies parent prefill messages and starts a fresh iteration budget. Parent conversation history is not passed. Workspace instructions can nevertheless be loaded into the child prompt. Child task IDs separate cwd records/file caches while initially sharing the parent cwd/container. Child persistence acquires a handle for the parent's Hermes transcript database. Model/provider/endpoint normally inherit; trusted delegation configuration can override them, and configured fallbacks/credential pools remain available. These are routing facilities, not Renulus's exact-subscription allowlist. [B construction][b-child], [C construction][c-child], [prompt][prompt], [task identity][task-id], [B routing][b-route], [C routing][c-route], [transcript connection][session-db].

3. **Stock delegation does not provide individual worker tool roles.** The model-facing builder passes `toolsets=None` for every child. Children inherit the parent surface minus named exclusions: delegation for leaves, clarification, memory writes, messaging and scheduling. C additionally blocks `start_chat`. The internal narrowing helper intersects parent toolsets but appends parent MCP toolsets by default; orchestrators regain delegation according to depth. A retrieval worker therefore needs a host-supplied catalogue and execution policy; a prompt saying “read only” does not enforce one. [B builder][b-builder], [C builder][c-builder], [B selection][b-tools], [C selection][c-tools].

4. **Budgets and cancellation are useful but incomplete host boundaries.** Defaults are depth 1, ten children per call, 250 iterations per child and no configured inactivity timeout; depth/concurrency settings have no hard ceiling. Async admission counts shared call slots, and capacity rejection falls back to synchronous execution. Direct Python calls default to synchronous execution; model-facing calls request background delegation, but hosts without completion delivery join synchronously. Accepted background children detach from parent cancellation; hosts need the separate session-scoped interrupt path. Cleanup releases registries, leases, tool resources and kernels, with deferred close for an unwinding worker. C adds a two-second stale-result collection grace. Cancellation remains cooperative. [limits][limits], [iterations][iterations], [dispatch][dispatch], [model/Python difference][model-dispatch], [async admission][async], [session stop][stop], [cleanup][cleanup], [B timeout][b-timeout], [C grace][c-grace].

5. **Process state and generation defaults need containment.** Registration uses process-global storage plus profile overlays; active-child/async records and resolved-tool-name snapshots are also process-global. Delegation locks construction and saves/restores the tool-name snapshot, rather than making catalogues inherently per-session. Fresh agents read configuration with three API attempts and five post-exhaustion recovery cycles by default. Invalid tool names/JSON also cause automatic model correction/retry; invalid `output_schema` results trigger one correction conversation at both pins. Failed correction still returns raw text with validation flags; “completed” is not domain acceptance. Parent finalization also calls its memory manager with child summaries. [registry scope][globals], [worker registries][worker-globals], [async globals][async-globals], [construction lock][lock], [B recovery][b-recovery], [C recovery][c-recovery], [B schema retry][b-schema], [C schema retry][c-schema], [tool-call correction][validation-retry], [memory callback][memory].

**Proposed adoption boundary:** register small domain tools around the existing Mem0 OSS, Docling/HybridChunker, FastEmbed and LanceDB services. Give evidence lookup, citation checking and practice drafting distinct scopes. Enforce source eligibility, project/learner ownership, assessment-key exposure, operation permissions and cancellation at execution, including delegated/MCP calls. Canonical writes and scoring stay in Renulus SQLite services; child text, transcripts and derived indexes cannot become canonical authority automatically. Retain personal Windows execution without owner-hosted inference or doctor-managed generative runtimes. Preserve the allowed Codex GPT 6.1 Sol/GPT 6 Astra/GPT 6 Luna or OpenCode Go MiMo V2.6 Pro/DeepSeek V4.1 Flash routes; disable fallback/pool rotation and all automatic generative retries, including schema repair. Own worker context and transcript retention to preserve saved-by-default, temporary and Archive semantics. These controls are proposed engineering work; current Renulus generation explicitly disables tools ([baseline adapter][renulus]).

**Uncertainty and reversal evidence:** source inspection does not prove approved-model tool calling, Windows cleanup, cross-session isolation or educational quality. Later authorised synthetic checks should cover unadvertised-tool attempts, MCP scope escape, stop during a canonical-write proposal, simultaneous profiles, background completion delivery and exact request-attempt counts. If these require pervasive patches or the approved subscriptions cannot support tools, Hermes becomes a weaker foundation for this requirement. Reliable upstream host injection and demonstrated bounded domain workers would strengthen it.
