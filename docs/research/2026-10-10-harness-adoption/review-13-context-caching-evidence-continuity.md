# Review 13 — Context, caching and evidence continuity

2026-10-10; source inspection, with no provider calls or runtime tests. Pins: Renulus `528025ff0b22477c12ee1512e0e7d15297a6e888`; bundled Hermes `af90026aa09949579bd423d24def3d38f743cde0`; inspected upstream Hermes `dce1e9b37581dd62e480a9064dc04a709c2940d3`; Pi 1.1.0 `abe508e1b89912adde45528136c3221eb69acdd7`; OpenCode v2/2.0.26 `55dde8810d8a859c0a21e42491ae7d5801fb49ef`. Findings concern these source snapshots; SDK publication does not establish artifact/source equivalence.

My judgment **on this axis** provisionally favors OpenCode v2's provider-provenance boundary, borrowing Pi's explicit usage invalidation and branch-reference handling, and Hermes's reference-only handoffs and compression-lineage cache scopes. This is conditional on host controls below, not a foundation-change decision. None makes summaries authoritative evidence or establishes cache savings, research accuracy, or educational quality.

Five verified facts matter:

1. **Usage anchors remain partial measurements.** Pi uses valid assistant usage plus estimated later messages; context edits or compaction invalidate older anchors ([raw lines 137–261](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/compaction/compaction.ts#L137-L261)). OpenCode similarly combines reported input/cache/output/reasoning tokens with estimates, including unseen tool results. Its anchor predicate matches the current **provider**, not necessarily the exact model; unknown windows do not trigger automatic compaction ([868–923](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/compaction.ts#L868-L923)). Hosts should label measured and estimated components separately.

2. **Pi has two distinct compaction contracts.** Coding-agent branch summaries collect the departed branch to its common ancestor and append mechanically collected read/modified file lists ([108–145](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/compaction/branch-summarization.ts#L108-L145), [367–380](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/compaction/branch-summarization.ts#L367-L380)). Separately, `pi-durable` commits the summary's model/options/history boundary, reads that immutable boundary, and admits nonblocking results through submissions that can settle stale ([134–174](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/compaction.ts#L134-L174), [401–435](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/compaction.ts#L401-L435)). This is stronger than transcript-only persistence, but its API is explicitly experimental, and compaction retains older entries ([README 1–7](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L1-L7), [336–349](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/README.md#L336-L349)).

3. **Pi warming is additional generation.** The coding-agent default is eligible active-run warming ([settings 19–21](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/docs/settings.md#L19-L21)). SDK validity compares selected provider/model and message-prefix object identities ([369–379](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/sdk.ts#L369-L379)); it does not compare external source revisions. Refresh sends a one-output-token request with retries disabled; failures are best-effort and warming may reschedule ([330–368](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/cache-warmer.ts#L330-L368)). Disable warming for adoption proofs and temporary scope.

4. **OpenCode bounds opaque continuity, but affinity shares ancestry.** Native checkpoint provenance includes provider/model, protocol, route and endpoint hash, with exact compatibility comparison ([18–54](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/provider-context.ts#L18-L54)); opaque reasoning replay is restricted to the producing model and excludes interrupted/error reasoning ([153–206](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/runner/to-llm-message.ts#L153-L206)). Child sessions share parent affinity; forks use their source's affinity ([6–8](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/affinity.ts#L6-L8)). That is cache routing, not authorization to inherit evidence. Summary compaction can use a separately configured compaction-agent model ([205–234](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/compaction.ts#L205-L234)).

5. **Hermes offers useful anchors with incompatible unrestricted fallback.** Upstream extracts bounded exact identifiers/URLs alongside its summary ([1043–1065](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/agent/context_compressor.py#L1043-L1065)); cache scopes survive compression rotations while ordinary forks are isolated, with a deliberate cache-parity exception ([1–8](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/agent/prompt_cache_scope.py#L1-L8), [80–99](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/agent/prompt_cache_scope.py#L80-L99)). A distinct auxiliary summary model can fall back to the main model even after access/quota failure ([4301–4325](https://github.com/NousResearch/hermes-agent/blob/dce1e9b37581dd62e480a9064dc04a709c2940d3/agent/context_compressor.py#L4301-L4325)). Renulus budgets with estimates, overrides summary dispatch/fallback and strips Codex replay/cache/native fields ([context 53–105](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/runtime/context.py#L53-L105), [transport 77–113](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/runtime/renulus/runtime/hermes.py#L77-L113)). Upstream capability is not current adapter behavior.

The retention risk is **derived material surviving a scope change**, not a demonstrated cross-user cache disclosure. Pi's summary updates preserve previous information ([540–575](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/coding-agent/src/core/compaction/compaction.ts#L540-L575)); OpenCode permits removing superseded content through summarization instructions ([145–173](https://github.com/anomalyco/opencode/blob/55dde8810d8a859c0a21e42491ae7d5801fb49ef/packages/core/src/session/compaction.ts#L145-L173)). Neither prompt is a deletion guarantee.

Proposed host controls:

- Stamp every summary, request snapshot and child result with conversation/branch, selected route, retention mode, instruction/tool schema hashes, source revisions and deletion epoch. Cancel pending work and reject late results when stamps change; discard opaque checkpoints that cannot be selectively scrubbed. Rotate cache affinity when scope changes. Rotation cannot promise provider-side erasure.
- Preserve a deterministic evidence manifest outside prose: source/revision/passage/page identifiers and claim-to-source links. Revalidate it at every turn and child handoff. SQLite retains canonical source, learner and assessment authority; Docling/FastEmbed/LanceDB and Mem0 remain reusable derived services. Upstream file/URL lists supplement this manifest.
- Gate primary, summary, branch, warming and child calls through the same selected-subscription/exact-model policy. Temporary conversations need isolated volatile child and summary state. Prevent saved transcripts, durable tasks or derived indexes from retaining their material implicitly.

The [October 6 rule](https://github.com/houraniiiii/Renulus/blob/528025ff0b22477c12ee1512e0e7d15297a6e888/docs/DECISIONS.md#L142-L152) covers visible authentication/quota/model/image rejection without automatic retries, fallback or subscription changes. The adapter's `max_retries=0` is the conservative proof baseline. For proofs, recovered in-flight generation must await explicit Retry; broader transient-network/restart policies remain proposals. Pi durable's request checkpoint can resend independently of error retries ([184–209](https://github.com/earendil-works/pi/blob/abe508e1b89912adde45528136c3221eb69acdd7/packages/durable/src/harness/generation.ts#L184-L209)). Auxiliary calls need the same gate.

Unresolved: selected subscription routes' actual checkpoint/reasoning/cache support, opaque-state retention and Windows restart behavior. Evidence that would change my preference: Pi durable proving explicit recovery gating and evidence-revision invalidation, or OpenCode failing those controls. Future synthetic proofs should delete a cited passage during compaction/child work, close temporary scope, change model, and restart; require no stale evidence or unapproved generation replay. No accuracy or cache-efficiency claim follows from these sources.

Handoff: `docs/research/2026-10-10-harness-adoption/review-13-context-caching-evidence-continuity.md`; conclusion: conditional OpenCode preference on this axis; strongest fact: native checkpoints have exact route/endpoint provenance; unresolved risk: retained opaque/summary/child state after source deletion.
