# Renulus development source register

Baseline verified against public primary-source pages on **October 4, 2026**;
the teaching-pack subset was reconciled on **October 7, 2026** as recorded below.
This is the **single current development source/acquisition list** for Renulus. It covers
public reuse, non-commercial material, member/institutional access, user-owned
files, bounded research use and optional retrieval APIs. Older research shortlists
are dated evidence and do not override this register.

The [owner’s recorded follow-up](planning/2026-10-04-user-answers.md) confirms ERA
user-responsible downloading as a supported direction and optional user-supplied
web/literature API keys. Specific supplied files, formats and use scopes are
recorded at acquisition. This register is a development plan and verified source
snapshot. A separate acquisition run was authorised later on October 4, 2026;
its external manifests report actual files and gaps. No working application
adapters, reviewed corpus or complete assessment bank are established here.

Each row identifies a source/channel, its verified edition/status, access and
use conditions, developer acquisition, a user acquisition method and its update
route. An entry that is reading-only, licensed-integration, watch-only or
latest-unverified remains in this one list; it is not an enabled current-evidence
corpus. Public access, source currency and processing rights are independent.

The per-user flows describe the intended product experience alongside existing
publisher/download mechanisms. Doctors obtain selected files or papers through
official links or app-managed public retrieval; bulk dataset links are also
provided for independent acquisition. No doctor-managed CLI, cloud account,
model server or full biomedical-corpus download is required.

## Acquisition and currency contract for implementation

For each acquired record, store the register ID, source owner and canonical
URL, DOI/PMID/PMCID where relevant, document/asset/item identity and revision,
publication and revision dates, final/draft/commentary/preprint status, scope and
jurisdiction, source review/expiry dates, retrieved/checked dates, checksum and
page/section/figure locators. Record the exact licence or permission reference,
attribution and access class. Store permitted display, caching, indexing/embedding,
model input, derivation, evaluation and redistribution separately. Training is
outside the confirmed direction. These are planned canonical SQLite records, not
a second remote data service or an implemented schema.

Use separate source-status fields for latest-final verification, clinical/content
review, correction, supersession (whole document or chapter), review-overdue,
retraction, repository removal and access/licence change. Overdue review means
reverification is needed; it is not proof that a guideline was superseded.
Unknown/unverified, expired, superseded or retracted material is excluded from
default current-guidance retrieval. Keep explicitly labelled historical records
when eligible and needed for citation/attempt provenance. A repository removal
is not automatically a scientific retraction; resolve the two states separately.

Cross-check guideline finals and publisher corrections before freshness-sensitive
answers and before publishing reviewed item keys. A failed check must remain
visible and must not refresh a current label. Recommended initial engineering
cadence: incremental literature checks daily while the app is online, official
guideline/ERA/product-information catalogue checks weekly, and an on-demand
canonical-source check when a current recommendation is requested. These
cadences are proposals to verify against supported interfaces and quotas; they
do not promise continuous monitoring while Windows/the app is offline.

Prefer the publisher/current guideline for edition and correction identity.
Use PubMed/Europe PMC for discovery, PMC/Europe PMC for eligible full text, and
Crossref plus publisher notices for deposited status relationships. OpenAlex
adds graph/discovery metadata. Apply dataset revisions and deletions; metadata
refresh, file revision and scientific correction are not interchangeable. A
missing correction/retraction flag is not proof that none exists. Deduplicate
the same publication across these channels by DOI/PMID/PMCID and preserve
manuscript versus version-of-record relationships.

For PMC, the new dataset README defines version-specific metadata and download
URLs. Use the returned XML/PDF/text/media URLs and checksums, or documented HTTPS
object listing. Do not open an article-version prefix as though it were a folder
URL. Filter actual article-version licence and retraction state; the broader
cloud dataset includes TDM manuscripts as well as the OA subset. The inventory
can lag continuous object changes. Exact live adapter rate/auth behaviours and
selective OAI/EFetch response formats still need integration verification.

Build a reviewed nephrology subset across the agreed general topics and ESENeph
objectives. Source-family membership or open access alone is not a quality filter.
Record study/article type and human review; classify final guidelines, research,
reviews, cases and preliminary findings separately. Preserve table headers,
units, footnotes and image/caption rights through the selected document pipeline.
Original questions/cases need source locators, one defensible reviewed key,
plausible distractors, rationale, reviewer/date and immutable versions. Keep
reserved evaluation items out of teaching retrieval and generated practice.

Authoring/review publishes a pack revision; an article or guideline change flags
affected objectives and items for review. Do not silently rewrite historical
attempts. Source/raw-file versions retained for a study are explicitly dated
evaluation snapshots, not advertised as live current guidance.
